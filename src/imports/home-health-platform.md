We are designing a best-in-class healthcare operations platform focused on Home Health and Hospice agencies.

The system must be significantly easier to use than existing healthcare software such as:
Alora, Axxess, WellSky, Netsmart, HHAeXchange, and similar platforms.

Most healthcare apps are cluttered, menu-driven, and difficult to navigate. This system must instead prioritize:

• operational speed
• clarity of patient context
• task-driven workflows
• exception-first design
• minimal cognitive load
• dense but readable information
• keyboard-friendly workflows

Users should almost never browse menus to find work.

Instead the system should guide users through:
• work queues
• alerts
• due items
• operational exceptions
• recent activity
• quick actions

The application should feel calm, professional, and extremely fast.

Important UX patterns to include:

Persistent Patient Context
Whenever a patient is selected, display a sticky patient header showing:
- patient name
- DOB / age
- MRN / account number
- office
- admission status
- payer tags
- discipline tags
- alerts
- quick actions
- selected admission switcher

Admission Context
Admissions are a primary operational entity. The UI must always make it clear which admission is active.

Workspace Driven Navigation
Home screens should not be dashboards with random metrics. They should be operational workspaces with prioritized queues.

Exception First Design
Problems must be visible immediately:
- missing signatures
- delayed visits
- EVV errors
- incomplete admissions
- authorization problems
- missing documentation
- HOPE / OASIS due

Fast Data Density
Users must see many patients or visits at once without overwhelming the UI.

Context Drawers
Use right-side drawers for secondary information instead of navigating away from the current screen.

Keyboard Productivity
Support command palette, quick search, and quick actions.

Design the application as a final product, not a prototype.
